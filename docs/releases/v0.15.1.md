# Fireworks v0.15.1

0.15.1 放开传输并发：模型与镜像、多个模型、多个镜像现在可以同时下载与分发，唯一保留的限制是同一份资源的重复操作——同一模型/镜像到同一台机器的重复分发，以及同一模型/镜像的重复真实下载。

## 变更

- **并发放开**：此前控制平面同一时间只允许一个外部下载源（模型 HF 下载与镜像 registry 拉取互斥），且同名资源只要存在进行中任务就不再接受新任务，即使目标机器完全不同。现在控制平面下载/拉取与节点分发都不再互相阻塞：一次发布可以同时启动全部缺失的模型与镜像传输，也可以把同一模型分发到不相交的节点集合（例如不同集群）。
- **只禁止重复**：同一模型/镜像 -> 相同机器（head 或任一 worker）的重复分发会被拒绝（同机同文件的并发写），同一模型/镜像的重复真实下载/拉取也会被拒绝（同写控制平面缓存/归档）。提示会带上冲突任务号与原因，便于判断是哪个任务在占用目标机器。
- **发布行为**：一次发布对所有缺失资源（模型与镜像、多个模型、多个镜像）分别启动传输并合并汇报，全部就绪后才创建任务。

## 升级

- 控制面与前端升级到 `0.15.1`。
- 本次节点 Agent 无变更，无需重部署；若仍在 0.15.0 之前、尚未按 0.15.0 说明重部署 Agent，请先完成那一步。
- 无新增数据迁移。

完整变更见 [CHANGELOG](https://github.com/skymaze/Fireworks/blob/v0.15.1/CHANGELOG.md)。
