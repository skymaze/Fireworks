# Fireworks v0.14.0

0.14.0 围绕「任务发布」补强：发布第二步改为买票式选座（head/worker 同一张节点卡片网格、占用节点置灰、空闲节点自动预选），并顺带修一个真实的稳定性缺陷——离线节点会把数据库连接池占满导致整站假死。

## 变更

- **发布节点选座**：发布第二步由「head 下拉 + worker 勾选清单」改为一张可选节点卡片网格，head 一并纳入；点击选中、再次点击取消。卡片直接标注 Head / Worker / 空闲 / 占用四态。
- **占用置灰**：被其它运行中任务承载的节点置灰并显示占用徽章与任务名，不可选中；「刷新」按钮重读集群占用并自动改选空闲节点（买票式连座：第一个空闲节点成为 head，固定拓扑配方自动补齐到所需台数）。
- **集群占用上报**：`/clusters/{id}/plan` 汇报各成员节点的占用状态，与创建任务时的节点互斥判定同源。
- **模型与镜像下载互斥**：控制平面同一时间只允许一个外部下载源（模型 / 镜像），避免同时抢管理平面带宽与磁盘 IO；已完整缓存的资源仅做分发，可与对方并发。
- **发布页细节**：「配方 / 集群」选项展示完整名称不再截断；删除任务后不再强制跳离当前页。
- **连接池假死修复**：多个端点在等待不可达节点的 agent 探测（5s × 3 重试）期间持有 ORM 会话，少数并发轮询即可把 SQLAlchemy QueuePool 占满、整站 DB 操作排队超时（表现为后端假死）。轮询型端点与三个后台循环改为「短会话读 → 无会话探测 → 短会话写」，探测期间不占连接池。
- **节点卡片更紧凑**：节点选择网格宽屏下增至 3~4 列，卡片内边距收窄，IP / RoCE / HCA 合并为一行，减少节点多时的空白与纵向滚动。

## 升级

- 控制面与前端升级到 `0.14.0`。
- 无节点 Agent 变更，无需重部署节点。
- 无新增数据迁移。

完整变更见 [CHANGELOG](https://github.com/skymaze/Fireworks/blob/v0.14.0/CHANGELOG.md)。
