# Fireworks v0.10.0

模型管理系统版本化重构收尾（阶段二~四）：0.9.0 把 HF 仓库的 commit sha 落库并实现多版本共存，这一版把「增量更新、版本切换、按版本分发、worker 差量直传、历史版本 GC、发布版本记录」一次补齐——模型从「下载/分发的黑盒」变成「可更新、可回滚、可钉扎、可追溯」的 git 式版本仓库。

## 变更

- **增量更新**：完整缓存的模型也可一键「更新到最新」，强制解析远端最新 commit 并按 blob 差量补齐（`snapshots/<sha>`、`trees/<sha>.json` 全部保留，想回退随时切回）。
- **版本切换与按版本分发**：发布页模型变量多了「发布版本」选择器（最新 + 各历史完整版本），任务按钉扎的 commit 分发；模型卡片的版本列表里每个完整版本可单独「分发此版本」。
- **节点精确校验 + worker 差量直传**：节点按目标 commit 精确校验（新 Agent 返回 `verify_sha` 与缺失文件清单），worker 只补缺失 blobs 与布局锚点，不再整仓重传；旧 Agent 自动退化，控制面不加区分。
- **清理历史版本（GC）**：一键清理不被引用、且超出保留个数（默认 3 个最新完整版本）的历史快照；活动任务 / refs 指向的版本永远保护，blobs 内容去重不删。
- **发布可追溯**：任务环境新增 `MODEL_SHAS`，与 `MODEL_IDS` 对齐记录每个模型发布时的精确 commit；`model_pins` 非法值直接拒绝。

## 升级

- 控制面与前端升级到 `0.10.0`。
- **节点 Agent 建议重部署**：新版 Agent 支持按 commit 精确校验，并把缺失文件清单交给控制面，worker 才能享受差量直传；旧 Agent 不升级仍可用（控制面按大小阈值回退），只是没有这两项优化。
- 无新增数据迁移（`model_downloads.sha` 复用 0.9.0 的幂等迁移，旧任务自动回填）。

完整变更见 [CHANGELOG](https://github.com/skymaze/Fireworks/blob/v0.10.0/CHANGELOG.md)。
