# Fireworks v0.2.1

Fireworks v0.2.1 是修复版本：修复删除集群后新建集群串数据、创建集群忽略手动网段、镜像传输 `docker load` 失败三个问题，并为受影响的开发版部署提供启动自愈迁移。

## Highlights

- **主键单调不复用（`clusters` / `nodes` / `recipes`）**：SQLite 默认会复用已删除的最大 ROWID，导致删除集群后遗留引用串到新建集群（表现为「新建集群出现上个集群数据」）。三张表统一启用 AUTOINCREMENT，启动时对旧库幂等迁移；中途中断的迁移残留（`*_legacy` 表）会自动恢复并把数据搬回。
- **创建集群按用户网段配置**：不再自动复用节点现有高速网络，始终按界面提供的网段规划并配置（弹窗自动填入空闲网段）；网段与现网冲突时提示并自动建议可用网段。移除独立的「网络预检」按钮，检测并入创建流程。
- **删除集群清理关联数据**：删除集群时一并清理其下已结束任务及历史数据（task_nodes / 推理统计 / 压测记录），不再保留失去集群引用的孤儿任务；未停止的任务仍须先停止。
- **镜像传输修复与加固**：docker-archive 组装支持 zstd 压缩层（buildah/podman 构建的镜像），修复 `docker load` 失败 `archive/tar: invalid tar header`；blob 下载 416 循环保护、Agent 端 416 断点续传兜底、发送结果校验与更明确的错误提示。
- **升级自愈**：曾运行含迁移缺陷开发版、出现「节点集群数据丢失」的部署，升级到 v0.2.1 后启动时会自动检测残留的 `*_legacy` 表并恢复数据，无需手工处理。

完整变更见 [CHANGELOG](https://github.com/skymaze/Fireworks/blob/v0.2.1/CHANGELOG.md)。

## Install or upgrade

发布流水线会把同一套多架构镜像同时推送到 GHCR 与阿里云 ACR。请选择一种部署方式：

### HTTP（仅本机或可信内网）

```bash
FW_IMAGE_TAG=0.2.1 COOKIE_SECURE=0 docker compose -f docker-compose.prod.yml up -d --pull always
```

### HTTPS（域名 + 反向代理）

```bash
FW_IMAGE_TAG=0.2.1 docker compose -f docker-compose.prod.yml up -d --pull always
```

中国大陆使用阿里云源：

```bash
FW_IMAGE_TAG=0.2.1 COOKIE_SECURE=0 docker compose -f docker-compose.prod.cn.yml up -d --pull always
```

### 升级注意

- 升级前建议备份 `fireworks-db` 卷；v0.2.1 启动时会对 `clusters` / `nodes` / `recipes` 执行一次主键单调性迁移（秒级，数据保留），并自愈上次升级中断的残留表。
- **必须重新部署节点 Agent**：v0.2.1 的 Agent 版本与 0.2.0 一致，但建议统一升级以保持能力对齐；旧 Agent 缺少 `image_peer_transfer_v1` 能力时镜像传输会在能力检查阶段明确报错并提示重新部署。
- 回滚：把 `FW_IMAGE_TAG` 改回上一版本并 `docker compose up -d`；数据库已迁移的表在旧版本下仍可正常读写（AUTOINCREMENT 对旧代码透明）。
