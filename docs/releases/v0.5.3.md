# Fireworks v0.5.3

任务名即 docker compose 项目名；本次把任务名校验对齐节点 **Docker Compose v5** 的硬性限制，并让发布失败时能看到真实原因。

## 变更

- 创建任务时任务名只允许**小写字母、数字及 `-`/`_`**（`^[a-z0-9][a-z0-9_-]*$`）：不能含点 `.`、大写或空格，非法名在发布前即返回明确的 `400 task_name_invalid`
- Agent `_validate_project` 同步收紧并返回带说明的 400（直接调用 Agent API 时同样是纵深防御）
- 发布失败时 `task.error` 透出 agent 返回的真实原因（如 `docker compose up 失败: invalid project name ...`），不再只显示 `502 Bad Gateway`
- 前端发布表单增加任务名提示与输入 pattern；更新 `task_name_*` / `task_name_invalid` i18n 文案

## 背景

v0.5.2 发布带点任务名（如 `glm5.3-flash-nv`，来自模型版本 `5.3`）时，节点 Docker Compose v5 拒绝该项目名，`compose up` 在任何拉镜像/启动之前失败 → 502，且用户看不到真实原因。

## 升级

- 控制面升级到 `0.5.3`；**无数据库迁移**。
- 节点 Agent 建议重部署（`/api/nodes/{id}/deploy-agent`）以获得一致的预校验（控制面已拦截时 Agent 侧为纵深防御）。
- 旧任务不受影响；以旧任务名重新发布（重建任务）时请遵守新命名规则。

完整变更见 [CHANGELOG](https://github.com/skymaze/Fireworks/blob/v0.5.3/CHANGELOG.md)。
