# Fireworks v0.14.1

0.14.1 聚焦任务发布的 rank 一致性问题：节点选择变化后 rank 不再自动压紧重排（可能留下空洞导致分布式启动失败），且越界 rank 能一路通过发布。

## 变更

- **节点 rank 自动重排**：发布第二步选择节点时，head/worker 变化（取消 head、移除 worker、节点被占用自动改选）后，rank 自动压紧为 0..N-1（head 恒为 0，worker 依次 1..N-1）；手动编辑过的相对顺序会被保留，增删节点后自动补位，不再留洞。
- **rank 越界校验**：发布页对手动输入的越界 rank（≥ 节点数）实时提示并禁用发布；后端在创建任务与配方预览时与前端同源校验（rank 唯一且覆盖 0..N-1），新增错误码 `task_rank_out_of_range`。此前这类非法组合会通过校验、到节点侧才以分布式启动失败暴露。

## 升级

- 控制面与前端升级到 `0.14.1`。
- 节点 Agent 仅版本号同步（无行为变更），无需重部署节点。
- 无新增数据迁移。

完整变更见 [CHANGELOG](https://github.com/skymaze/Fireworks/blob/v0.14.1/CHANGELOG.md)。
