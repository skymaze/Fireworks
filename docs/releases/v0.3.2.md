# Fireworks v0.3.2

Fireworks v0.3.2 是 patch 版本：修复发布任务页「模型缓存状态」卡片不显示。平台控制平面的模型保障在后端 v0.3.1 已改为按 `picker=="model"` 动态识别模型变量，但前端发布页仍按 `DSPARK_MODEL` 键名硬编码解析模型仓库，导致模型变量使用其它键名的配方（DeepSeek b12x `SPARK_MODEL`、GLM `GLM52_MODEL_PATH`、Qwen `SGLANG_MODEL`）在发布页看不到节点模型缓存状态，也无法使用页内「发送模型」与发布前模型就绪校验/解锁。

## 修复亮点

- **发布页模型识别与后端对齐**：按配方 `picker=="model"` 的变量动态解析模型仓库，任意键名均能显示「模型缓存状态」卡片，并恢复「模型未就绪时页面内发起传输 → 就绪后解锁发布」的完整链路。
- 镜像侧（`picker=="image"`）本就为动态取键，行为不受影响；前端 typecheck 通过、unit tests 4/4 通过。

## 升级

- 控制平面升级到 `0.3.2`；节点 Agent 仅版本号同步、无功能改动，无需重部署。
- 无数据格式与任务语义变化，无需额外迁移。
- 升级前建议备份 `fireworks-db` 卷。

## 部署

```bash
# 公网源（GitHub GHCR）
FW_IMAGE_TAG=0.3.2 docker compose -f docker-compose.prod.yml up -d --pull always

# 国内源（阿里云 ACR）
FW_IMAGE_TAG=0.3.2 docker compose -f docker-compose.prod.cn.yml up -d --pull always
```

仅本机或可信内网的纯 HTTP 部署加 `COOKIE_SECURE=0`。镜像标签 `v0.3.2` 由发布 CI 构建并推送 GHCR 与阿里云 ACR。

完整变更见 [CHANGELOG](https://github.com/skymaze/Fireworks/blob/v0.3.2/CHANGELOG.md)。
