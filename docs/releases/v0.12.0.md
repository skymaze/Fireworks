# Fireworks v0.12.0

0.12.0 修复模型仓库中空文件（size 0）导致的快照完整性校验误判，以及两个发布页问题：模型版本钉扎下拉框错位（无历史版本时输入行下方多出一个重复输入框）、表单提示在窄视口把 label 压成逐字竖排。

## 变更

- **空文件纳入快照完整性**：下载同步此前跳过 `size<=0` 的文件，导致其快照 symlink 悬空（blob 从未创建），`_verify_snapshot` 永远把它们报为缺失，修复/重试都无法自愈。现在为每个空文件创建内容寻址的 0 字节 blob（按 manifest `blobId` 校验，与普通文件一致），快照布局完整。带空文件（如 `__init__.py`）的仓库可校验通过，已损坏的旧缓存会在下次下载/修复时自愈。
- **模型版本钉扎下拉错位（发布页）**：模型变量的「发布版本」选择器此前位于变量输入链中间，把 select/bool/文本输入的 `v-else-if/else` 分支错误挂到钉扎条件上；对无历史版本的模型变量和所有镜像变量，会在输入行下方多渲染一个重复输入框。已把钉扎选择器移到输入链之后，使各分支正确按变量类型判定。
- **表单提示窄视口换行**：Nuxt UI FormField 默认把 label 与 hint 放在同一不换行的 flex 行，窄列中长中文 label + 长 hint 会被挤到逐字竖排。为 labelWrapper 加 `flex-wrap`、hint 加 `min-w-0`，溢出的 hint 换行到独立一行，不再压坏 label。

## 升级

- 控制面与前端升级到 `0.12.0`。
- 无节点 Agent 变更，无需重部署节点。
- 无新增数据迁移；损坏的旧缓存（空文件悬空）会在下次下载/修复时自动补齐。

完整变更见 [CHANGELOG](https://github.com/skymaze/Fireworks/blob/v0.12.0/CHANGELOG.md)。
