# Fireworks v0.15.0

0.15.0 让模型分发更可诊断、更可直接使用：head 节点回拉失败不再只报裸 500 而是给出真实原因（并修掉文件名特殊字符导致的回拉 404），发布任务时模型与镜像可以同时分发，下载完成的模型还会平铺成可直接 `cp -r` 拷贝的真实文件目录。

## 变更

- **模型平铺镜像（可直接拷贝）**：平台缓存是 Hugging Face hub 布局（`blobs/` + `snapshots/<sha>/` 符号链接），直接拷贝只会得到符号链接。现在控制平面与各节点在下载/分发完成后，把当前激活版本平铺成真实文件目录：控制平面默认 `/data/cache/models-files`（`MODEL_FILES_DIR` 可覆盖），节点默认 `~/.cache/huggingface/models`（`FW_MODEL_FILES_DIR` 可覆盖）。同文件系统用硬链接（几乎不占额外磁盘），跨文件系统回退为复制；只保留当前激活版本，切换版本清理旧文件，删除模型时一并删除；已有的完整缓存打开本地模型列表即自动补生成。
- **发布同时分发模型与镜像**：此前发布时模型未就绪就返回 409，镜像保障不会执行——一次发布只能启动一类传输，另一类要等重新发布。现在一次发布同时启动所有缺失资源的传输（两类传输可并发，仅「模型下载 + 镜像拉取」这类真实外部下载保持既有互斥），提示信息里列出各类传输任务号；发布按钮不再因资源未就绪而禁用，未就绪时发布即启动传输，也可继续用「发送模型 / 发送镜像」按钮查看进度。
- **回拉失败给出真实原因**：head 节点 Agent 从控制平面回拉模型文件或镜像归档失败时，此前直接抛出 `500 Internal Server Error`，控制平面任务错误只显示 httpx 原文，无法定位。现在 Agent 返回 502（控制平面明确 4xx/5xx，带状态码、原因与响应摘要）或 504（断流/超时/IO），控制平面提取结构化文案写入任务错误。
- **回拉 URL 编码修复**：模型文件回拉 URL 现在对 repo / relpath 做 URL 编码。文件名含 `&`、`#`、`+`、空格、`%` 等字符时，此前 query 会被截断或污染，控制平面按错误路径返回 404，节点再以 500 上报；普通文件名的 URL 保持不变。

## 升级

- 控制面与前端升级到 `0.15.0`。
- 本次节点 Agent 有行为变更（回拉错误映射、平铺镜像、删除模型时清理镜像目录），升级控制面后请重新部署所有节点 Agent。
- 无新增数据迁移；沿用已有 `fireworks-db` 与缓存卷即可，平铺镜像会自动补生成（硬链接，不额外占盘）。

完整变更见 [CHANGELOG](https://github.com/skymaze/Fireworks/blob/v0.15.0/CHANGELOG.md)。
