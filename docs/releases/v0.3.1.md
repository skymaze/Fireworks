# Fireworks v0.3.1

Fireworks v0.3.1 是 patch 版本：修复平台发布任务时的"模型保障"链路对模型变量键名的硬编码（`DSPARK_MODEL`），使新增 DeepSeek b12x（`SPARK_MODEL` 键）、GLM（`GLM52_MODEL_PATH` 键）等非该键名配方，在控制平面发布时同样触发模型卡片/清单检查、下载并分发到节点、就绪后强制离线加载。

## 修复亮点

- **模型保障对键名通用化**：发布时按配方 `picker=="model"` 的变量动态解析模型仓库，不再只认 `DSPARK_MODEL`；避免"模型卡片没检查、节点缺模型也不自动分发"的静默失效。
- **规范键 `MODEL_ID`**：发布时把模型仓库写入统一键（与 `send_model` 开关解耦），终止任务删模型、推理统计一律取用；老配方（`DSPARK_MODEL`）数据兼容回退。
- 新增两条 create_task 回归测试锁定上述行为（`SPARK_MODEL` 键触发模型保障 / 关闭 `send_model` 仍注入 `MODEL_ID`）。

## 升级

- 控制平面升级到 `0.3.1`；节点 Agent 无改动，无需重部署。
- 无数据格式与任务语义变化，无需额外迁移。
- 升级前建议备份 `fireworks-db` 卷。

## 部署

```bash
# 公网源（GitHub GHCR）
FW_IMAGE_TAG=0.3.1 docker compose -f docker-compose.prod.yml up -d --pull always

# 国内源（阿里云 ACR）
FW_IMAGE_TAG=0.3.1 docker compose -f docker-compose.prod.cn.yml up -d --pull always
```

仅本机或可信内网的纯 HTTP 部署加 `COOKIE_SECURE=0`。镜像标签 `v0.3.1` 由发布 CI 构建并推送 GHCR 与阿里云 ACR。

完整变更见 [CHANGELOG](https://github.com/skymaze/Fireworks/blob/v0.3.1/CHANGELOG.md)。
