# Fireworks v0.8.0

发布任务支持多模型配方：一个配方可声明多个模型变量（如主模型 + DSPARK 投机解码草稿模型），发布页逐模型检查并分发，任一模型未就绪都会阻止发布；删除任务时也能按清单一次清理全部模型。

## 变更

- **多模型发布（新增）**：配方每个 `picker=model` 变量都作为一个需要保障的模型——发布前逐模型检查各节点缓存（缺失则走管理传输：控制平面下载 → 管理网发送 head → Agent 高速直传 worker），模型状态卡片按仓库分块展示各节点就绪情况；「发送模型」按序补齐全部缺失模型。
- **多模型删除（新增）**：发布时 `MODEL_ID` 记录主模型，新增 `MODEL_IDS` 记录全部模型；删除任务勾选「同时删除节点模型」时一次删除该任务用到的所有模型。
- **镜像同理（新增）**：`picker=image` 变量支持多个，逐个保障镜像分发。

## 修复

- 发布此前只检查/分发第一个 `picker=model` 变量：含两个模型（主模型 + 草稿模型）的配方，草稿模型会被静默忽略而不下发；现在每个模型都会在发布会话内保障就绪。

## 升级

- 控制面与前端升级到 `0.8.0`，节点 Agent 无需重部署；存量单模型配方行为不变。
- 需要多模型分发的配方，把对应模型变量标记为 `picker=model` 即可。

完整变更见 [CHANGELOG](https://github.com/skymaze/Fireworks/blob/v0.8.0/CHANGELOG.md)。
