# Fireworks v0.15.2

0.15.2 让「节点磁盘写满」这类故障有明确提示：Agent 部署前预检剩余空间并在不足时给出可操作的报错，模型传输写盘失败也直接点明磁盘不足，不再表现为不透明的 `Failure` 或被误判为网络问题。

## 变更

- **Agent 部署磁盘预检**：部署（重装/升级）在 SFTP 上传前执行 `df -Pk` 检查目标分区剩余空间，需要容纳 Agent 文件、离线依赖 wheelhouse 与节点上 venv 创建/安装的开销；不足时直接失败并提示「节点磁盘空间不足：剩余 X，至少需要 Y」，附带清理建议。此前磁盘写满时 SFTP 只返回不带 errno 的 `Failure`，界面上看不出原因，而且旧 Agent 会继续运行，表现为「部署失败但版本没变」。`df` 不可用时预检自动跳过，不引入新的失败面。
- **模型回拉磁盘写满的明确报错**：节点写入模型文件时磁盘写满（ENOSPC）现在返回 507「节点磁盘空间不足，无法写入模型文件」，不再落入「控制平面回拉失败(网络/IO)」的分类。

## 升级

- 控制面与前端升级到 `0.15.2`。
- 本次节点 Agent 有行为变更（磁盘满错误分类），需重新部署节点 Agent；与 0.15.0 的 Agent 行为变更（回拉错误映射、平铺镜像）一次重部署同时生效。
- 无新增数据迁移。
- 运维提示：节点磁盘写满通常来自历史 Docker 镜像与模型缓存。重部署前先 `df -h /` 确认剩余空间，清理不再使用的镜像/模型版本；控制面模型列表与节点详情可查看占用。

完整变更见 [CHANGELOG](https://github.com/skymaze/Fireworks/blob/v0.15.2/CHANGELOG.md)。
