# Fireworks v0.6.1

健康检查改为 Portainer 式只读语义：健康判定回归 Docker 自身 healthcheck，模型加载较久的任务不再被控制面固定超时误判为 error，容器 transient `unhealthy` 也不再被打成红错；恢复由 Docker 自身 healthcheck 完成。

## 变更

- **移除固定超时判死**：发布/启动/重启后的健康检查不再用 900s 定时「判超时」——模型加载期间 Docker 仍在 `starting` 宽限期，控制面只按需补读健康快照（默认 60s 采样窗），此后由 30s 监控循环持续刷新；长加载任务不再被误判为「健康检查超时」error。
- **`unhealthy` 不再置任务 error**：容器 `unhealthy` 只以健康徽标展示（异常），任务保持 running；任务生命周期只由容器状态决定（全部容器 exited -> stopped）。
- 配置项 `TASK_HEALTH_TIMEOUT` 更名为 `TASK_HEALTH_STEADY_WINDOW`（仅作首次读数采样窗，不再是终态判据）。

## 升级

- 控制面升级到 `0.6.1`；**无数据库迁移**，节点 Agent 无需重部署。
- 若模型冷启动时长超过配方声明的 `start_period`，建议同步调大该配方的 `start_period`；否则 Docker 在宽限期后仍会把容器健康判为「异常」徽标（任务状态不受影响，随服务就绪自动转回健康）。

完整变更见 [CHANGELOG](https://github.com/skymaze/Fireworks/blob/v0.6.1/CHANGELOG.md)。
