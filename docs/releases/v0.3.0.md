# Fireworks v0.3.0

Fireworks v0.3.0 是 minor 版本：新增「添加节点时执行初始优化」功能，并修复镜像分发的断流失败问题、参考模型分发链路对 pulling / packing / loading 三个阶段做并行化提速，同时保证「已存在且完整的归档/层」绝不重复下载。

## Highlights

- **添加节点时执行初始优化（新功能）**：新增节点并部署 Agent 成功后（默认开启，可关闭），SSH 以 root 依次执行 4 项优化并调度重启——关闭 Wi-Fi/蓝牙、关闭图形界面、授予 docker 权限、禁用 swap。整体 best-effort，单项失败/取不到 root 不阻断添加节点，结果写入节点 `optimize_result` 并在前端节点详情展示。
- **断流续传，不再整体失败**：Agent 归档拉取任意中断（管理网/RoCE 抖动、代理截断）都保留 `.part` 分片并按 Range 断点续传（有界重试）；416 在 urllib 实际抛出的 HTTPError 层处理。此前任一阶段中断会让整个分发任务直接失败。
- **离线也可分发已缓存镜像**：控制平面已有该镜像归档时，不再强依赖 registry 可达；registry 不可达/受限网络下线仍可把缓存镜像分发给节点（仅无缓存且查不到镜像才报错）。
- **pulling / packing / loading 三步并行化**：registry 各层并行下载（默认 4）、归档组装时各层并行解压后再按 manifest 顺序写 tar（输出字节与指纹不变）、head 与 worker 的 `docker load` 并行执行（总耗时从「各节点求和」降为「最慢节点」）。
- **不重复下载/不重复重算**：已存在且完整的归档与层通过 size+mtime 标记（控制平面 `.digest` sidecar、Agent `.verified` 标记）直接跳过下载且不再整份重读；标记失效才回退全量 sha256 校验。目标节点持有旧 digest 时仍会正常重新传输（因为「不是最新」）。
- 并行度可用 `IMAGE_PULL_LAYER_WORKERS` / `IMAGE_PACKING_WORKERS` 调整。

完整变更见 [CHANGELOG](https://github.com/skymaze/Fireworks/blob/v0.3.0/CHANGELOG.md)。

## Install or upgrade

发布流水线会把同一套多架构镜像同时推送到 GHCR 与阿里云 ACR。请选择一种部署方式：

### HTTP（仅本机或可信内网）

```bash
FW_IMAGE_TAG=0.3.0 COOKIE_SECURE=0 docker compose -f docker-compose.prod.yml up -d --pull always
```

### HTTPS（域名 + 反向代理）

```bash
FW_IMAGE_TAG=0.3.0 docker compose -f docker-compose.prod.yml up -d --pull always
```

中国大陆使用阿里云源：

```bash
FW_IMAGE_TAG=0.3.0 COOKIE_SECURE=0 docker compose -f docker-compose.prod.cn.yml up -d --pull always
```

### Dev 提测（阿里云源 dev 镜像）

本版本开发阶段的 dev 镜像也推送至阿里云 ACR，方便在正式发布前验证节点初始优化与镜像分发修复/提速：

```bash
FW_IMAGE_TAG=dev COOKIE_SECURE=0 docker compose -f docker-compose.prod.cn.yml up -d --pull always
```

镜像：`registry.cn-shanghai.aliyuncs.com/aixn-public/fireworks-backend:dev`、`registry.cn-shanghai.aliyuncs.com/aixn-public/fireworks-frontend:dev`。

### 升级注意

- 升级前建议备份 `fireworks-db` 卷。v0.3.0 不改变既有数据格式与任务语义，无需额外迁移；启动时为旧库幂等补建 `nodes.optimize_result` 列。
- 分发链路的断流续传与并行化对节点 Agent 版本有要求：**建议重新部署节点 Agent 到 `0.3.0`**，以启用断流续传与命中跳过快路径；旧 Agent 仍可完成分布（能力协商时报错会提示重新部署）。
- 节点初始优化默认在添加节点时开启（`optimize_on_add` 可关闭），best-effort 不阻断添加；优化包含调度重启，请在预期维护窗口内添加节点。
- 回滚：把 `FW_IMAGE_TAG` 改回上一版本并 `docker compose up -d`。
