# Fireworks v0.2.0

Fireworks v0.2.0 将推理监控改为被动统计真实 vLLM 流量，并增加 Agent 版本提醒，避免控制平面与节点能力不一致。

## Highlights

- Agent 被动读取 vLLM `/metrics` 的累计计数器、KV Cache gauge 与延迟直方图，不再发送合成推理请求，也不会额外占用模型吞吐。
- 后端按任务对完整原始快照做区间差分，展示 Decode / Prefill tok/s、请求数、TTFT P95、E2E、KV Cache、窗口合计与趋势，并支持最近 1 小时 / 24 小时窗口。
- 离散的区间差分指标使用柱状图；Token 图统一展示 Decode / Prefill tok/s，请求数按自身单位独立成图，KV Cache 时点指标保留折线。
- 图表按时间桶聚合，但完整源区间仍参与总量、峰值和延迟统计；空闲期滚动维护边界快照，下一次流量不会被整段空闲时间摊薄。
- KV Cache 是 vLLM 的瞬时 Gauge；摘要展示窗口峰值，图表桶内保留最大采样值，空闲压缩也会保留 gauge 变化；Agent 将 `/metrics` 有界读取上限提高到 8 MiB，避免大指标页截断 KV 行。
- 节点列表与详情页始终显示 Agent 安装按钮；版本低于、高于或等于控制平面时分别显示“升级 Agent”“降级 Agent”或“重装 Agent”。
- 启动时自动补建推理查询索引并删除旧版派生格式样本；没有表字段或业务数据迁移。

完整变更见 [CHANGELOG](https://github.com/skymaze/Fireworks/blob/v0.2.0/CHANGELOG.md)。

## Install or upgrade

发布流水线会把同一套多架构镜像同时推送到 GHCR 与阿里云 ACR。请选择一种部署方式：

### HTTP（仅本机或可信内网）

```bash
FW_IMAGE_TAG=0.2.0 COOKIE_SECURE=0 docker compose -f docker-compose.prod.yml up -d --pull always
```

### HTTPS（域名 + 反向代理）

```bash
FW_IMAGE_TAG=0.2.0 docker compose -f docker-compose.prod.yml up -d --pull always
```

中国大陆将文件名换成 `docker-compose.prod.cn.yml`。HTTP 模式不要暴露到公网；HTTPS 部署保持默认 Secure Cookie，并参考仓库中的 nginx 示例配置证书与反向代理。

v0.2.0 可直接复用 v0.1.1 的 `fireworks-db`。启动时会幂等补建推理查询索引并删除旧版派生格式的推理统计样本；没有表字段或其它业务数据迁移。升级前仍建议备份数据库卷。

### 必须重新部署 Agent

v0.2.0 控制平面使用新的 `/api/inference/stats` Agent 接口。控制平面升级完成后，请在节点页面逐一点击“升级 Agent”，直到所有节点显示 `v0.2.0` 且不再出现版本警告。旧版 Agent 可以继续上报基础资源和日志，但无法提供新的推理统计。
