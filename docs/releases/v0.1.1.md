# Fireworks v0.1.1

Fireworks v0.1.1 简化模型与镜像管理流程，并修复任务详情页重入后无法查看容器日志的问题。

## Highlights

- 模型搜索移至 Header 弹窗，搜索结果和直接下载均为单击后立即下载，不再经过“下载 / 下载并分发”的二次选择。
- 已下载模型和镜像从缓存/归档列表点击“分发”，统一使用“先选集群、再选节点”的弹窗；节点默认全选，第一个选中节点为 head。
- 后端拒绝未加入集群和跨集群的模型、镜像分发请求，避免错误地跨集群传输。
- 任务运行一段时间后重新进入详情页，会重置日志视图并回放离开期间的缓存，恢复容器日志显示。
- ECharts 与 zrender 使用独立缓存 chunk，生产构建不再产生超过 500 KB 的客户端 JavaScript 文件。

完整变更见 [CHANGELOG](https://github.com/skymaze/Fireworks/blob/v0.1.1/CHANGELOG.md)。

## Install or upgrade

发布流水线会把同一套多架构镜像同时推送到 GHCR 与阿里云 ACR。请选择一种部署方式：

### HTTP（仅本机或可信内网）

```bash
FW_IMAGE_TAG=0.1.1 COOKIE_SECURE=0 docker compose -f docker-compose.prod.yml up -d --pull always
```

### HTTPS（域名 + 反向代理）

```bash
FW_IMAGE_TAG=0.1.1 docker compose -f docker-compose.prod.yml up -d --pull always
```

中国大陆将文件名换成 `docker-compose.prod.cn.yml`。HTTP 模式不要暴露到公网；HTTPS 部署保持默认 Secure Cookie，并参考仓库中的 nginx 示例配置证书与反向代理。

本版本没有数据库结构变更，可直接复用 v0.1.0 的 `fireworks-db`。升级前仍建议备份数据库卷；控制平面升级后应重新部署节点 Agent，使组件版本保持一致。

## Verification

- 登录后打开模型页，从 Header 搜索并单击一个结果，确认立即开始下载。
- 在模型缓存或镜像归档中发起分发，确认只能选择同一集群成员且默认全选。
- 打开运行中的任务日志，离开详情页一段时间后再次进入，确认近期日志可以回放并继续实时更新。
