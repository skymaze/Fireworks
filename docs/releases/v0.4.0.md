# Fireworks v0.4.0

Fireworks v0.4.0 带来任务生命周期优化：**意外退出 / 手动停止的任务可直接「启动」，运行中任务可直接「重启」，两者都复用已有容器、不重建、不丢容器状态**——不再需要删除后重新发布。

## 核心变化

- **「停止」不再删除容器**：从 `docker compose down`（移除容器）改为 `docker compose stop`（项目级停止、**保留容器**，GPU 随即释放）。因此停止后的任务可以一键「启动」复用。
- **「启动」（stopped / error 状态）**：`docker compose start` 复用已停止容器快速拉起；仅当容器已被清理（如历史版本删除或外部清理）时，自动回退到 `docker compose up` 用首次发布配置重建，老任务也能顺利恢复。
- **「重启」（running 状态）**：`docker compose restart` 进程级重启，容器与文件系统保留，不重建。
- 启动 / 重启拉起 vLLM 后自动补发健康检查（模型加载与端口就绪等待），从点击到 `running` 的体验与发布一致。
- 任务详情页与列表页新增对应按钮（中英文文案）。

## Agent 变更

- Agent 新增 `POST /api/compose/action`（`stop | start | restart`）端点，保留项目的基 argv 数组执行与 project 名校验风格。

## 升级（重要）

- **控制平面与节点 Agent 均需升级到 `0.4.0`；升级控制平面后请重新部署各节点 Agent**，否则任务停止/启动/重启会明确报错提示（旧 Agent 无 `/api/compose/action`）。
- 节点 Agent 重新部署沿用既有「重装/升级 Agent」入口；`0.4.0` 的大版本号用于标识「需重部署 Agent」（与 v0.2.0 同一机制）。
- 数据格式与任务语义无破坏性变化，无需额外迁移；升级前建议备份 `fireworks-db` 卷。

## 行为提示

- 「停止」后容器保留在节点上（`exited` 状态，占少量磁盘），GPU 已释放；需要彻底释放磁盘请使用「删除」。

完整变更见 [CHANGELOG](https://github.com/skymaze/Fireworks/blob/v0.4.0/CHANGELOG.md)。
