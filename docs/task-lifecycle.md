# 任务发布、日志与数据生命周期

## 发布时的节点信息

配方中的节点级自动变量可能依赖 GPU、HCA、GID、网卡和磁盘信息。发布任务和生成
发布预览时，控制平面会并发调用所有已选节点的 Agent `/api/info`，成功后更新节点
快照，再进行配方渲染。任一节点不可达或信息读取失败时，本次操作直接失败，不会
回退使用添加节点时保存的旧参数。

集群的高速网地址仍以已经验证并提交的 `network_plan` 为准；节点刷新用于补齐当前
硬件能力，不会绕过集群网络规划。

## 容器日志

详情页通过一条 `docker logs -f --tail 1000` 流先回放最近日志，再无缝继续接收实时
日志，不再使用“HTTP 快照后再订阅”的双请求方式，因此两阶段之间没有丢行窗口。
控制平面为同一容器保留最多 1500 个日志段、合计最多 2 MiB 的回放缓存，后打开的
页面也能先看到近期历史；Agent 重连后会清空旧缓存并重新回放最近 1000 行。

浏览器端日志缓冲最多保留约 2 MB，以避免长期运行页面无限占用内存。任务日志 API
仍可用于按 `tail` 数量读取容器快照。

## 删除任务

`Task` 是任务节点、推理探针样本和压测结果的聚合根。删除任务时，控制平面会在同一
事务内删除对应的 `TaskNode`、`InferenceSample` 和 `TaskBenchmark` 数据。独立的只增
任务 ID 分配账本会保留每次分配，已有数据库和新建数据库都不会把已删除的任务 ID
分配给新任务；任务表本身在新建数据库中也使用 SQLite `AUTOINCREMENT`。

由于当前 SQLite 数据库出于其它软引用兼容原因没有全局启用外键约束，启动迁移还会
清理旧版本遗留的任务域孤儿记录。总览查询也会忽略不存在任务的压测记录，避免旧数据
影响峰值统计。
